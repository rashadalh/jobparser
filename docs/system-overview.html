System overview

Resume-Driven Job Matching with LangGraph

A state-machine architecture that uses Adzuna for job discovery, full job-description extraction for evidence, and specialized LLM nodes for resume parsing, search planning, requirement parsing, and fit judgment.

Adzuna discovery Resume profile cache Full JD required Structured LLM outputs LangGraph fan-out

What the system does

The product promise is narrow and useful: only show jobs where the final job description was extracted and the candidate's resume appears to meet the stated requirements.

Parse once Resume text is normalized and fingerprinted. Known resumes load an existing structured profile instead of re-calling the LLM.
Search broadly The resume profile becomes a validated Adzuna search plan with query terms, location, employment type, exclusions, and limits.
Fetch evidence Each Adzuna result resolves to its final URL. The system extracts full JD text before making any qualification decision.
Judge strictly A fit judge compares structured resume evidence against structured job requirements and only passes high-confidence fits.

Top-level state machine

LangGraph orchestrates deterministic code and specialized LLM nodes through shared state. The job evaluation step fans out across many independent workers.

01

Extract resume text

Parse PDF, DOCX, or plain text into normalized resume text.

02

Fingerprint resume

Create stable file and text hashes with parser/schema versions.

03

Load or parse profile

Use cached resume profile when available; otherwise call the resume LLM.

04

Plan Adzuna searches

Translate the candidate profile into validated API search queries.

05

Run Adzuna search

Fetch pages of results, preserve source metadata, and capture URLs.

06

Dedupe jobs

Merge repeated listings by final URL, company, title, and location.

07

Evaluate jobs

Fan out workers that fetch full JDs, parse requirements, and judge fit.

08

Aggregate matches

Return only qualified jobs and keep failures for audit/debugging.

Resume profile cache

The cache is application state, not just a LangGraph checkpoint. Checkpoints resume graph runs; the resume cache avoids repeating expensive semantic parsing across runs.

Cache hit

Load the stored resume profile and continue straight to search planning. The run records that the profile came from cache.

Cached?

Cache miss

Call the resume profiler LLM, validate the profile, store it with versioned hashes, and continue with the new profile.

LLM agents as graph nodes

Each LLM has one job, one schema, and one failure mode. This keeps the workflow inspectable and makes it possible to debug why a job passed or failed.

R

Resume profiler

Converts resume text into a candidate profile with roles, skills, seniority, experience, domains, authorization hints, locations, and claim-level evidence.

  • Input: normalized resume text
  • Output: ResumeProfile
  • Cached by text hash and parser version
S

Search planner

Converts the resume profile into a bounded set of valid Adzuna API queries. It expands role synonyms but cannot invent unsupported API parameters.

  • Input: ResumeProfile
  • Output: list of AdzunaQuery
  • Validated before API calls
J

JD requirement parser

Reads full job-description text and extracts required skills, preferred skills, experience, education, location constraints, responsibilities, and dealbreakers.

  • Input: extracted full JD text
  • Output: JobRequirements
  • Runs only after text quality checks pass
F

Fit judge

Compares resume evidence with parsed requirements and returns a strict decision: qualified, not qualified, or uncertain.

  • Input: resume profile plus job requirements
  • Output: FitJudgment
  • Must cite resume evidence for met requirements

Job evaluation subgraph

Once jobs are deduped, each one goes through the same evidence pipeline. This is a strong candidate for a reusable LangGraph subgraph.

Resolve URL Follow the Adzuna redirect and save the final canonical URL.
Fetch page Retrieve static HTML or render the page when the content requires it.
Extract JD Prefer ATS-specific parsers and JobPosting JSON-LD, then readable text.
Parse requirements Use the JD parser LLM to produce structured requirements.
Judge fit Compare candidate evidence against hard requirements and dealbreakers.

Qualification rules

The final visible result set should be generated by normal code, not by asking the LLM which jobs to show.

Required gate

Full JD extraction

  • Resolved final URL exists
  • Extracted text passes length and noise checks
  • Requirement parser returns valid structured output
Fit gate

Evidence-backed match

  • No failed dealbreakers
  • No missing hard requirements
  • Resume evidence exists for each met requirement
Confidence gate

Strict display threshold

  • decision == "qualified"
  • confidence >= 0.75
  • Uncertain and failed jobs stay out of the main feed

Implementation posture

Use LLMs for semantic interpretation, and use code for control. LangGraph owns state transitions, retries, fan-out, checkpointing, and aggregation. The LLM nodes produce strict JSON only. The application layer validates every object, applies thresholds, stores cache records, and explains each match with traceable evidence.
